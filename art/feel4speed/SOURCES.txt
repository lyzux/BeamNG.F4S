  Feel4Speed uses the camera pipeline's world velocity magnitude for movement
  speed, rather than wheel speed or a wind-dependent signal.

  Feel4Speed implements its own bounded, token-checked numeric queue requests;
  it does not install a persistent vehicle publisher or require UI streams.

Lateral-G roll references for 0.2.2:
https://documentation.beamng.com/modding/vehicle/coordinate_systems/
  Vehicle +X is left, -Y is forward, +Z is up. Normalized world forward XY
  therefore yields left=(-forwardY,forwardX) for projected cornering acceleration.
https://github.com/KRtkovo-eu-AI/BeamNG-ADAS-plus/blob/main/.beamng/orig-0.36/lua/common/mathlib.lua
  Quaternion products, inverse quaternion/vector action, radian Euler inputs
  and toDirUp (local Y forward, local Z up). Camera-local right roll requires
  negative native Euler-Y premultiplied with the current camera quaternion.
  This was numerically verified using the retained implementation, including
  nonidentity camera orientations; no engine file is shipped with the mod.
https://github.com/KRtkovo-eu-AI/BeamNG-ADAS-plus/blob/main/.beamng/orig-0.36/lua/ge/extensions/core/cameraModes/driver.lua
  Native inertial camera motion also derives from GE world data.vel.
https://github.com/KRtkovo-eu-AI/BeamNG-ADAS-plus/blob/main/.beamng/orig-0.36/lua/vehicle/sensors.lua
https://github.com/KRtkovo-eu-AI/BeamNG-ADAS-plus/blob/main/.beamng/orig-0.36/lua/vehicle/hydros.lua
  Sensors gx/gx2 and lateral-acceleration use inspected for coordinate context.
  Feel4Speed computes horizontal motion-based lateral G directly in GE and
  adds no Vehicle Lua polling, sensor publisher or network dependency for roll.

The original roll-geometry test fixture covers opposite sign/composition
negative controls and preservation of the view axis across rotated cameras.
